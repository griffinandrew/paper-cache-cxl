# Summary of Changes: PMem Eviction Stacks Feature

## What Changed

Modified the latest merged commit that added eviction stacks to PMem to use a dedicated feature flag instead of sharing flags with the object table.

## Key Changes

### Feature Flag Independence
BEFORE: Eviction stacks used same flags as object table
- `alloc_with_hash` → Both objects and eviction in PMem
- No flag → Both in DRAM

AFTER: Eviction stacks have independent flag
- `alloc_with_hash` alone → Objects in PMem, eviction in DRAM
- `pmem_eviction_stacks` alone → Objects in DRAM, eviction in PMem
- Both flags → Both in PMem
- No flags → Both in DRAM (default)

### Safety Improvements (Addressing Segfaults)

1. **Null Pointer Check**: Added check in dealloc() before freeing memory
2. **Pre-allocation**: Reserve capacity before operations to prevent mid-operation allocation failures
3. **Bounds Checking**: Use get() instead of direct indexing to prevent out-of-bounds access
4. **Capacity Checks**: Verify capacity before Vec insertions

## Usage

### Enable PMem Eviction Stacks
```bash
cargo +nightly build --features alloc_with_hash,pmem_eviction_stacks
```

### Keep DRAM Eviction Stacks (default or with PMem objects)
```bash
cargo build                                        # All DRAM
cargo +nightly build --features alloc_with_hash    # PMem objects, DRAM eviction
```

## Addressing the Segfault Issue

The implementation includes multiple safety improvements to prevent segfaults:

1. **Allocator Level**: Null pointer checks before deallocation
2. **Data Structure Level**: Pre-allocation and capacity checks
3. **Access Level**: Bounds-checked array access
4. **Documentation**: Comprehensive debugging guide

See SEGFAULT_FIXES.md for technical details and PMEM_EVICTION_STACKS_DEBUGGING.md for troubleshooting.
